Build Summary
====================================================================

Scope: Production-ready backend (FastAPI + PostgreSQL + SQLAlchemy 2.0).

2. DOMAIN RULES ENFORCED
--------------------------------------------------------------------
- Users: single table + role enum. Vendors pre-provisioned only.
  Students self-register on first successful OTP verify (name required).
- Orders belong to one student + one vendor; OrderItem snapshots
  item_name and price_at_order at creation (menu edits never corrupt
  past orders). Random 6-digit pickup_token generated with uniqueness
  retry.
- Order status state machine (lookup table seeded on startup + on demand):
  placed -> accepted | rejected(reason)   (vendor)
  accepted -> preparing                   (vendor)
  preparing -> ready                      (vendor)
  ready -> picked_up                      (vendor)
  placed -> cancelled                     (student only)
- Transitions enforced server-side in order_service; student may cancel
  only while status == placed; only the owning vendor/student may act.
- Auth flow: OTP (no passwords). OTP is bcrypt-hashed before storage.
  Rate-limited per phone per rolling window -> 429. Verify caps wrong
  attempts; most-recent unused/unexpired OTP checked. JWT issued with
  role + sub embedded on success.
- Pricing: server recomputes total from current vendor prices; the
  client-sent total is never trusted.
- All CRUD ownership checks are done (menu item, order access).
--------------------------------------------------------------------
3. AUTH GUARDS
--------------------------------------------------------------------
- get_current_user: decodes Bearer JWT, checks access token type,
  reloads user from DB.
- get_current_student: 403 unless role == student.
- get_current_vendor: 403 unless role == vendor.

4. API SURFACE
--------------------------------------------------------------------
Student:
  GET  /api/v1/student/vendors              list open vendors
  GET  /api/v1/student/vendors/{id}/menu    view available menu
  POST /api/v1/student/orders               place order
  GET  /api/v1/student/orders               list own orders
  GET  /api/v1/student/orders/{id}          single order (owner-only)
Vendor:
  PATCH /api/v1/vendor/shop/toggle          toggle shop open/closed
  GET   /api/v1/vendor/menu                 list own menu
  POST  /api/v1/vendor/menu                 create menu item
  GET   /api/v1/vendor/menu/{id}            get menu item
  PATCH /api/v1/vendor/menu/{id}            update menu item
  DELETE/api/v1/vendor/menu/{id}            delete menu item
  GET   /api/v1/vendor/orders               list incoming (status filter)
  GET   /api/v1/vendor/orders/{id}          get order
  PATCH /api/v1/vendor/orders/{id}/status   transition status
Auth:
  POST /api/v1/auth/request-otp
  POST /api/v1/auth/verify-otp
  POST /api/v1/auth/refresh             rotate access & refresh token pair
  GET  /api/v1/auth/me
Admin:
  POST /api/v1/admin/vendors            provision vendor (protected by X-Admin-Key)
Health:
  GET  /health
--------------------------------------------------------------------
5. VENDOR ONBOARDING (ADMIN API)
--------------------------------------------------------------------
Vendors cannot self-register. To onboard a new canteen stall, call the Admin
provisioning API with the secret ADMIN_API_KEY:

  # Generate key: openssl rand -hex 32
  curl -X POST http://localhost:8080/api/v1/admin/vendors \
    -H "Content-Type: application/json" \
    -H "X-Admin-Key: <ADMIN_API_KEY>" \
    -d '{"phone_number": "9876543210", "name": "Campus Stall", "shop_name": "Campus Stall"}'

Note: This endpoint is strictly internal and never exposed to the public UI.
--------------------------------------------------------------------
6. RUNNING LOCALLY
--------------------------------------------------------------------
  cp .env.example .env       # configure secrets
  docker compose up -d        # start Postgres + FastAPI backend
  docker compose exec api alembic upgrade head

  cd frontend
  npm install
  npm run dev                 # start Vite dev server on http://localhost:5173
